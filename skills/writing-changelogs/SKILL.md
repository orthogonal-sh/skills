# Writing Changelogs

Use this skill when drafting or revising changelogs for a product, library, or internal release.

## Workflow

1. Gather the release range, merged PRs, issues, commits, and migration notes.
2. Group changes by user-facing category such as added, changed, fixed, deprecated, and removed.
3. Translate implementation details into concrete user impact.
4. Call out breaking changes, upgrade steps, and required configuration.
5. Keep entries short, specific, and linkable to source PRs or issues.

## Checks

- Do not include unreleased or private work unless requested.
- Separate internal refactors from visible behavior changes.
- Preserve exact version numbers, dates, and package names.
- Make the first section useful for readers deciding whether to upgrade.
