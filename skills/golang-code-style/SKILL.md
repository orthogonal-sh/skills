# Golang Code Style

Use this skill when writing or reviewing Go code for idiomatic readability and maintainability.

## Workflow

1. Inspect package boundaries, exported APIs, naming, receiver usage, and file organization.
2. Prefer simple control flow, clear errors, narrow interfaces, and standard-library conventions.
3. Run `gofmt` and the repo's existing lint/test commands when available.
4. Keep comments useful for exported symbols or non-obvious design choices.
