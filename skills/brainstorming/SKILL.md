# Brainstorming & Ideation

Structured techniques for generating ideas, solving problems creatively, and breaking through mental blocks. Use these frameworks when asked to brainstorm, ideate, or think creatively about any topic.

## Core Principles

1. **Quantity over quality** — generate many ideas first, evaluate later
2. **Defer judgment** — don't critique during generation
3. **Build on ideas** — combine, extend, and riff on what exists
4. **Seek wild ideas** — outlandish ideas often lead to practical breakthroughs
5. **Stay visual** — sketches, maps, and diagrams unlock different thinking
6. **Time-box** — constraints boost creativity; set a timer

## SCAMPER Method

Take an existing idea/product/concept and systematically transform it:

### **S — Substitute**
What can you replace? Materials, people, processes, components?
- What if we replaced the login form with biometric auth?
- What if the instructor was AI instead of human?
- What if we used SMS instead of email for notifications?

### **C — Combine**
What can you merge? Features, ideas, products, audiences?
- Combine a calendar with a to-do list → time-blocked task manager
- Combine a recipe app with a grocery store → meal kit service
- Combine code review with pair programming → live collaborative review

### **A — Adapt**
What can you borrow from another domain? Analogies, parallels?
- How do games handle onboarding? Apply that to SaaS
- How does Spotify do recommendations? Apply that to job matching
- How does Duolingo build habits? Apply that to fitness

### **M — Modify** (Magnify / Minimize)
What if you made something bigger, smaller, more frequent, less frequent?
- What if the free tier had no limits?
- What if the meeting was 5 minutes instead of 30?
- What if we checked in daily instead of weekly?

### **P — Put to Another Use**
What other problems could this solve? Who else could use it?
- A project management tool repurposed for wedding planning
- An inventory system adapted for personal collections
- A CRM used for managing personal relationships

### **E — Eliminate**
What can you remove entirely? Features, steps, roles?
- What if there was no signup required?
- What if we removed the dashboard entirely?
- What if there were no meetings?

### **R — Reverse / Rearrange**
What if you flipped the order, reversed roles, or rearranged the layout?
- What if customers set their own prices?
- What if junior devs reviewed senior devs' code?
- What if the checkout came before product selection?

## Six Thinking Hats (de Bono)

Look at a problem from six perspectives, one at a time:

### 🎩 White Hat — Facts & Data
What do we know? What data do we have? What's missing?
- "Usage dropped 15% last month"
- "We have 3,000 active users"
- "We don't know why users churn after week 2"

### 🎩 Red Hat — Feelings & Intuition
What's your gut reaction? No justification needed.
- "This feels overcomplicated"
- "I'm excited about this direction"
- "Something about this approach feels wrong"

### 🎩 Black Hat — Caution & Risks
What could go wrong? Devil's advocate.
- "Users might find this confusing"
- "This violates GDPR if we're not careful"
- "The engineering cost is 3x what we estimated"

### 🎩 Yellow Hat — Benefits & Optimism
What's the best case? What value does this create?
- "This could reduce onboarding time by 50%"
- "This positions us ahead of competitors"
- "Users have been asking for exactly this"

### 🎩 Green Hat — Creativity & Alternatives
New ideas, alternatives, possibilities.
- "What if we approach this completely differently?"
- "Here's a wild idea..."
- "What would [company/person] do?"

### 🎩 Blue Hat — Process & Meta
Managing the thinking process itself.
- "Let's focus on green hat for 10 minutes"
- "We've spent too long on black hat, let's move to yellow"
- "Let's summarize what we've decided"

## Mind Mapping

Start with a central concept, then branch outward:

```
                    ┌─ Performance
                    │    ├─ Bundle size
                    │    ├─ Caching
                    │    └─ CDN
                    │
Central Topic ──────┼─ User Experience
                    │    ├─ Onboarding
                    │    ├─ Navigation
                    │    └─ Mobile
                    │
                    ├─ Monetization
                    │    ├─ Freemium
                    │    ├─ Usage-based
                    │    └─ Enterprise
                    │
                    └─ Distribution
                         ├─ SEO
                         ├─ Partnerships
                         └─ Community
```

Rules for effective mind maps:
1. Use single words or short phrases on branches
2. Color-code branches by theme
3. Add images/icons where possible
4. No hierarchy judgment — it's a web, not a list
5. Go at least 3 levels deep on each branch
6. Connect branches that relate to each other

## Constraint-Based Creativity

Paradoxically, constraints boost creativity. Use these artificial constraints:

### Time Constraints
- "If we had to ship this in 24 hours, what would we build?"
- "What's the 1-hour version of this feature?"

### Resource Constraints
- "If we had no budget, how would we solve this?"
- "If one person had to build this, what would they cut?"

### Technology Constraints
- "How would you build this with only HTML and CSS?"
- "What if we couldn't use a database?"

### Audience Constraints
- "How would you design this for a 5-year-old?"
- "How would you design this for someone who's never used a computer?"

### Inversion
- "How would we make this product WORSE?"
- "What would guarantee failure?"
- Then flip each answer into a positive.

## The 10x Framework

Force yourself beyond incremental thinking:

1. **Current state:** Describe what exists today
2. **10% better:** What's the obvious incremental improvement?
3. **2x better:** What would you need to change to double the impact?
4. **10x better:** What would you need to fundamentally rethink?

Example — Customer support:
- **Current:** Email support, 24h response time
- **10% better:** Canned responses, 18h response time
- **2x better:** Live chat with AI triage, 1h response time
- **10x better:** Product so intuitive that support volume drops 90%

## Rapid Ideation Techniques

### Worst Possible Idea
Generate intentionally terrible ideas, then flip them:
1. "The worst way to do onboarding is to require a 50-field form"
2. Flip: "What if onboarding was zero fields? Just start using it."

### Random Input
Pick a random word, image, or concept. Force connections:
- Random word: "lighthouse" → How is our product like a lighthouse? → It should guide users through darkness (confusion) → Better contextual help system

### How Might We (HMW)
Reframe problems as opportunities:
- Problem: "Users forget to come back"
- HMW: "How might we make returning feel rewarding?"
- HMW: "How might we become part of users' daily routine?"
- HMW: "How might we bring value to users even when they're not using us?"

### Crazy 8s (Design Sprint)
1. Fold paper into 8 rectangles
2. Set timer for 8 minutes
3. Sketch one idea per rectangle (1 minute each)
4. No erasing, no overthinking
5. Review and star the best concepts

## Evaluation Frameworks

After generating ideas, evaluate them:

### Impact/Effort Matrix

```
          High Impact
               │
    Quick      │      Big Bets
    Wins  ★★★  │  ★★
               │
───────────────┼───────────────
               │
    Fill-ins   │   Money Pits
    ★          │   ✗
               │
          Low Impact

    Low Effort ──── High Effort
```

### ICE Scoring
Rate each idea 1-10 on:
- **Impact:** How much will this move the needle?
- **Confidence:** How sure are we this will work?
- **Ease:** How easy is this to implement?

Score = (Impact × Confidence × Ease) / 3

### RICE Scoring (for product features)
- **Reach:** How many users will this affect per quarter?
- **Impact:** How much will it affect each user? (3=massive, 2=high, 1=medium, 0.5=low, 0.25=minimal)
- **Confidence:** How confident are we in estimates? (100%, 80%, 50%)
- **Effort:** Person-months to implement

Score = (Reach × Impact × Confidence) / Effort

## Running a Brainstorming Session

### Structure

1. **Define the challenge** (5 min) — clear problem statement, no solutions yet
2. **Diverge** (20 min) — generate ideas using techniques above
3. **Cluster** (10 min) — group similar ideas into themes
4. **Converge** (10 min) — vote/score top ideas
5. **Refine** (15 min) — develop top 2-3 ideas further

### Rules to Set

- No "yes, but..." — use "yes, and..."
- Write ideas down (shared doc, whiteboard, sticky notes)
- One conversation at a time
- Encourage building on others' ideas
- Quantity goal: set a target number (e.g., "Let's get 50 ideas in 15 minutes")
