# Reviewing Technical Prose

Use this skill when reviewing docs, README changes, runbooks, specifications, proposals, changelogs, or support-facing explanations.

Prioritize factual errors and misleading instructions first, then confusing structure, undefined terms, stale assumptions, incomplete examples, and places where the reader cannot safely act.
