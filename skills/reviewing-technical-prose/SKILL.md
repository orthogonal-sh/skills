# Reviewing Technical Prose

Use this skill when reviewing docs, specs, runbooks, READMEs, changelogs, or technical posts.

## Workflow

1. Identify the target reader, purpose, and required level of detail.
2. Check factual accuracy against source code, APIs, examples, or product behavior.
3. Improve structure so the reader gets the answer in the right order.
4. Remove ambiguity, filler, stale claims, and unsupported promises.
5. Suggest concrete edits with examples when the issue is subtle.

## Checks

- Do not rewrite voice unnecessarily.
- Preserve terms of art and exact API names.
- Flag missing prerequisites, examples, limitations, and failure cases.
- Make the review more useful than merely grammatical.
