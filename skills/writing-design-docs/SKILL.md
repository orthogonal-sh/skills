# Writing Design Docs

Use this skill when planning a technical change that needs written design review.

## Workflow

1. Capture problem statement, goals, non-goals, constraints, and stakeholders.
2. Summarize current system behavior and relevant code paths.
3. Compare viable options with tradeoffs, risks, and migration cost.
4. Propose the design, rollout plan, observability, and rollback strategy.
5. List open questions and review decisions.

## Checks

- Keep claims grounded in code, docs, or measured behavior.
- Make tradeoffs explicit instead of hiding them in prose.
- Include failure modes and operational ownership.
- Update the doc as decisions change during implementation.
