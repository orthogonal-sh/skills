# Diagramming Processes

Use this skill when a workflow or process needs a diagram.

## Workflow

1. Identify actors, triggers, states, decisions, handoffs, and terminal outcomes.
2. Choose the simplest useful format: flowchart, sequence, state machine, or swimlane.
3. Label steps with domain language and avoid implementation noise.
4. Add exceptions, retries, escalations, and manual approvals where they matter.
5. Validate the diagram against a real example before sharing.

## Checks

- Keep diagrams readable at the target display size.
- Avoid crossing lines and ambiguous decision labels.
- Make ownership clear for each handoff.
- Pair diagrams with short notes when edge cases need prose.
